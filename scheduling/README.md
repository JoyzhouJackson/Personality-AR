# S01 合成批处理演示

本目录全部订单、部件、容量、工时和场景均为从零生成的虚构演示数据，用于演示批处理排产算法，不代表任何实际产品、企业或设备。

[在线演示](https://joyzhoujackson.github.io/workcell-simulation-demo/scheduling/)可比较立即启动与限时等单，也可编辑合成工时。保存后的配置只存于当前浏览器。

## 合成数据

输入工作簿为 `inputs/synthetic-orders.xlsx`，含说明、参数、装盘组合、场景及两张订单表。每单由 A、B、C 三种虚构部件组成，A/B 合计为 2 件、C 为 1 件，整套在同一盘处理。

共享盘面容量为 32 个等效位置，C 每件占 2 个位置，其余部件每件占 1 个位置。因此每盘最多处理 8 个整单。工作簿只列出 1–8 套的有效组合，整盘处理分钟数依次为 **18、25、31、38、44、51、57、64**。准备、后处理、批间切换时间依次为 **4、7、3 分钟**。这些数值是直接设置的合成表，不是现场测量或由实际工时推算。

样例包含 12 单/2 台与 24 单/3 台两个静态场景；所有设备在虚构的排产起点空闲。准备和后处理在设备外进行，可与处理和切换并行。同一设备的相邻批次保留设定切换时间。

## 运行

在本目录安装 `requirements.txt` 中的依赖后：

```shell
python run.py
python run_arrival_experiment.py
```

第一条运行静态排产并输出到 `outputs/static-schedule.html`。第二条生成单文件网页 `../docs/scheduling/arrival-comparison.html`，其模拟在浏览器内计算。两条命令均默认读取合成工作簿，可用 `--input` 指定其他本地输入；本地实际数据不应提交到公开仓库。

静态求解器使用动态规划最小化平均订单流动时间。输出前校验订单唯一分配、整套同盘、装盘容量、批处理工时、同设备批次无重叠及逐单完成时间。

## 随机到单比较

网页默认 24 单、3 台设备、平均到单间隔 5 分钟、最长等单 2 分钟。第一单在第 0 分钟到达，后续间隔按指数分布抽样，取整且至少为 1 分钟。两种策略使用相同到单序列，以减少样本差异。

两种策略均按先到先排，满盘立即启动。限时等单从设备可准备且已有待排订单时计时，新增订单不重置时限。最后一单到达后保留已派工批次，使用共同的收尾求解器最小化平均订单流动时间。

目标为每单的 **后处理完成时间 − 订单到达时间** 的平均值。页面同时展示批次甘特图、平均流动时间、总完工时间及配对差的 95% 置信区间；可扫描到单间隔，显示两种策略曲线与估计交叉点。仅当置信区间表明限时等单更快时推荐等待，否则优先立即启动。

网页支持修改订单量、设备数量、平均到单间隔、等单上限以及批次工时。技术输入范围用于控制浏览器计算量，不表示实际产能限制。
